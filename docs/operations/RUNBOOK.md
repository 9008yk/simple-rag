# 运维 Runbook

## 1. 使用说明

本文档用于本地和未来部署环境中的常见故障定位。当前生产部署尚未实现，因此部分恢复步骤需要在上线前补充具体命令和路径。

## 2. 基础检查

后端健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

预期：

```json
{"status":"ok"}
```

查看端口：

```powershell
Get-NetTCPConnection -LocalPort 8000,5173 -State Listen
```

查看数据目录：

```powershell
Get-ChildItem D:\vue3-program\simple-rag\data -Force -Recurse
```

## 3. 后端无法启动

检查：

1. 当前目录是否为 `backend`。
2. 虚拟环境依赖是否安装。
3. `8000` 端口是否被占用。
4. `SIMPLE_RAG_DATA_DIR` 是否可写。
5. SQLite 文件是否损坏或被锁定。

处理原则：

- 不直接删除数据库。
- 先备份 `data/app.db`。
- 检查应用日志和异常堆栈。

## 4. 前端无法连接后端

检查：

1. FastAPI 是否监听 `127.0.0.1:8000`。
2. Vite 代理是否指向 `http://127.0.0.1:8000`。
3. 浏览器 Network 请求的路径是否为 `/health` 或 `/api/*`。
4. 是否有代理或防火墙拦截。

## 5. SQLite database is locked

检查：

1. 是否存在长时间未提交的事务。
2. 是否有异常进程持续占用数据库。
3. `busy_timeout` 是否生效。

处理：

- 停止发出重复写入的重试请求。
- 等待当前写入完成。
- 不要通过删除锁文件解决。
- 如果问题持续，备份数据库并分析事务边界。

## 6. 磁盘空间不足

现象：

- 上传返回 `507`。
- SQLite 写入失败。
- Chroma 无法持久化。

处理：

1. 确认磁盘剩余空间。
2. 备份必要数据。
3. 清理确认无用的临时文件。
4. 不对未知上传文件直接执行批量删除。
5. 恢复空间后重新上传或重新处理。

## 7. Chroma 数据异常

检查：

1. `data/chroma/` 是否存在且可写。
2. collection 是否与当前 Embedding 模型一致。
3. 文档是否错误地停留在 `processing`。
4. SQLite 中的 `document_id` 是否仍存在。

处理：

- 先备份 Chroma 目录。
- 不直接手工修改向量数据。
- 对失败文档执行清理并重新处理。

## 8. LLM 或 Embedding API 失败

检查：

1. API Key 是否有效。
2. Base URL 和模型名称是否正确。
3. 是否触发限流或超时。
4. 请求费用或配额是否耗尽。

处理：

- 不在日志中输出密钥。
- 失败文档进入 `failed` 并记录 `error_message`。
- 确认服务恢复后再重试。

## 9. 回滚

```text
停止新版本
-> 恢复兼容的应用版本
-> 恢复对应数据库和 Chroma 备份
-> 运行健康检查
-> 验证文档列表和问答
```

没有经过恢复演练的备份不能视为可靠备份。

## 10. 事故记录

事故结束后记录：

- 发生时间和影响范围。
- 用户可见现象。
- 发现方式。
- 根因。
- 临时恢复步骤。
- 永久修复。
- 新增测试和监控。
