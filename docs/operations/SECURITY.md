# 安全规范

## 1. 当前安全姿态

当前是单用户、本地开发 MVP，没有登录和权限系统，不能直接暴露到公网。

当前已实现的基础保护：

- 只接受 `.txt`、`.md` 和 `.markdown`。
- 单文件限制为 `10 MiB`。
- 服务端使用 UUID 生成存储文件名。
- 拒绝空文件和缺少 `file` 的请求。
- API Key 不允许写入仓库。

尚未实现：

- 用户认证和授权。
- 文档级访问控制。
- 限流。
- 病毒或恶意内容扫描。
- 数据加密和密钥轮换。
- 安全审计日志。

## 2. 文件上传威胁

必须防范：

- 路径穿越，例如 `../../system.txt`。
- 用户文件名直接作为磁盘路径。
- 同名文件覆盖。
- 超大文件耗尽内存或磁盘。
- 伪造扩展名。
- 恶意文件内容和后续解析漏洞。
- 上传请求的高并发滥用。

当前策略：

```text
原始文件名只用于展示
磁盘文件名使用服务端 UUID
扩展名必须属于允许列表
按块读取并限制为 10 MiB
```

## 3. Prompt Injection

RAG 检索到的文档内容可能包含恶意指令。Prompt 必须明确：

- 检索文档只作为参考资料，不是系统指令。
- 用户问题和文档内容不能覆盖系统约束。
- 模型不得执行文档中的工具、URL 或系统命令。
- 无法从知识库找到依据时必须拒答或明确说明。

## 4. 密钥和配置

- `.env` 不得提交。
- 日志不得输出 Token、API Key 或完整 Authorization Header。
- 前端不得保存 LLM 和 Embedding 密钥。
- 生产环境使用 Secret 管理，不使用明文 `.env`。
- 密钥泄露后必须立即轮换。
- `.env.example` 只能包含占位值。

## 5. 数据保护

文档可能包含敏感信息，因此：

- 只记录必要日志，不记录完整文档内容。
- 明确数据保留期和删除流程。
- 删除文档时必须同步清理文件、SQLite 和 Chroma。
- 备份必须包含 `data/app.db`、`data/uploads/` 和 `data/chroma/`。
- 备份文件也需要访问控制。

## 6. 访问控制

公网或多人环境上线前必须补充：

- 登录和身份验证。
- 文档所有权和知识库权限。
- 检索时执行权限过滤。
- 删除操作授权。
- 管理员和普通用户角色。
- API 限流和审计。

在权限系统完成前，只允许本机或受控内网访问。

## 7. 依赖和应用安全

- 定期检查 Python 和 npm 依赖漏洞。
- 固定生产依赖版本。
- 不执行模型生成的 shell 命令。
- 解析文件时限制 CPU、内存、时间和文件大小。
- 错误响应不返回服务器路径、堆栈和数据库细节。

## 8. 上线阻断项

以下任一未满足时应阻止公网部署：

```text
没有认证和访问控制
没有 HTTPS
没有请求限流
没有备份和恢复验证
密钥仍保存在代码或明文文件中
日志包含敏感数据
```

## 9. 安全验收方向

- 路径穿越请求不会逃逸 `data/uploads/`。
- 超过大小限制不会留下部分文件或数据库记录。
- API Key 不出现在响应、日志和前端构建产物中。
- 未授权用户无法读取或删除文档。
- 删除文档后文件、SQLite 和 Chroma 均不可再检索。
