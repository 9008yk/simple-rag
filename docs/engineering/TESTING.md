# 测试策略

## 1. 文档职责

本文档定义测试层级、测试隔离、命令、覆盖要求和 PR 合并门槛。

测试用例内容以 `docs/product/MVP.md` 的 AC 和实际测试代码为准，不单独维护重复的测试用例表。

## 2. 测试层级

| 层级 | 当前状态 | 目标 |
| --- | --- | --- |
| 后端单元和接口测试 | 已实现 | 覆盖所有 API、错误和数据库副作用 |
| 数据库迁移测试 | 已实现 | 覆盖旧结构升级和数据保留 |
| 前端类型检查和构建 | 已实现 | 每个前端 PR 必须通过 |
| 前端组件测试 | 待实现 | 覆盖状态、交互和错误提示 |
| 端到端测试 | 待实现 | 覆盖上传、列表和未来问答主流程 |

## 3. 当前后端命令

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest -q
```

后端测试必须使用 `tmp_path` 和 `SIMPLE_RAG_DATA_DIR`，不得修改真实 `data/app.db` 和 `data/uploads`。

## 4. 当前前端命令

```powershell
cd frontend
pnpm build
```

构建当前等价于 TypeScript 检查和 Vite 生产构建。

## 5. 当前覆盖范围

上传接口：

- 合法 Markdown 上传。
- TXT 和扩展名规则。
- 同名文件创建独立文档。
- 空文件。
- 不支持的文件类型。
- 超过 10 MiB。
- 缺少 `file` 字段。
- 数据库失败时清理文件。
- 文件存储异常。

列表接口：

- 空列表。
- 上传后可见。
- 创建时间倒序。
- 不返回 `file_path`。

数据库：

- 表约束。
- 索引。
- 旧表迁移。
- 迁移后数据保留。

文档摄取：

- Markdown 标题上下文保留。
- 800/120 字符切分。
- 摄取成功后 Chroma chunk 数量和 SQLite 记录一致。
- Embedding 或解码失败时进入 `failed`。
- 服务重启时将中断的 `processing` 文档标记为 `failed`。
- 上传后后台任务被调度。

## 6. 测试隔离

| 资源 | 隔离方式 |
| --- | --- |
| SQLite | 每个测试使用临时目录 |
| 上传文件 | 每个测试使用临时目录 |
| Chroma | 未来使用独立临时 collection 或目录 |
| LLM | 使用测试替身，禁止真实调用 |
| 时间 | 使用固定时间或可注入时钟 |

## 7. 前端测试目标

后续引入 Vitest 后至少覆盖：

- 初始化请求成功和失败。
- 文件选择和本地校验。
- 上传中禁用。
- 上传成功刷新列表。
- API 错误展示。
- 空列表状态。

浏览器端测试可以后续引入 Playwright。

## 8. PR 合并门槛

每个 PR 必须：

- 只包含一个功能或修复切片。
- 通过相关后端测试。
- 前端改动通过 `pnpm build`。
- 接口改动同步 `docs/contracts/API_CONTRACT.md`。
- 数据库改动同步 `docs/contracts/DATABASE_CONTRACT.md` 和迁移测试。
- 前端交互改动同步 `docs/engineering/FRONTEND_SPEC.md`。
- 不包含 `.env`、密钥、数据库和上传文件。

## 9. Definition of Done

```text
代码完成
+ 契约更新
+ 测试通过
+ 手动验证完成
+ 无未解决 P0/P1 问题
+ 工作区只包含本次任务文件
```

不能用“AI 已生成代码”代替测试结果，也不能只检查状态码而忽略数据库和文件副作用。
