# 简单 RAG 知识库问答 MVP

## 1. 项目目标

构建一个可以在本地运行的简单 RAG 知识库问答应用：

1. 上传文档。
2. 将文档解析、切分并写入向量库。
3. 根据用户问题检索相关片段。
4. 调用大模型生成回答。
5. 返回回答对应的来源文档和片段。

## 2. 使用场景

- 单用户使用。
- 本地或单机部署。
- 文档量较小，采用轻量的本地存储方案。
- 以验证 RAG 主流程为目标，不追求复杂的生产级能力。

## 3. MVP 范围

### 3.1 文档管理

- 上传 `TXT` 和 `Markdown` 文档。
- 查看已上传文档列表。
- 查看文档处理状态。
- 删除文档。

### 3.2 文档处理

- 读取上传文件。
- 提取纯文本。
- 将文本切分为 chunk。
- 为 chunk 生成向量。
- 将文本和元数据写入向量库。
- 将文档元数据写入关系数据库。

### 3.3 问答

- 输入自然语言问题。
- 从向量库检索相关 chunk。
- 使用检索结果构造提示词。
- 调用大模型生成回答。
- 通过 SSE 流式返回回答。
- 返回回答引用的文档和 chunk。

### 3.4 会话

- 创建问答会话。
- 保存用户问题和助手回答。
- 保存回答对应的来源信息。
- 查询已有会话和消息。

## 4. 暂不实现

- Agent、工具调用、LangGraph。
- 登录、权限和多租户。
- PDF、Word、扫描件和 OCR。
- Rerank 和混合检索。
- Redis、Celery、MySQL、PostgreSQL。
- MinIO 或其他对象存储。
- Pinia 和 Webpack。
- 微服务、消息队列和分布式部署。

## 5. 用户流程

```text
用户上传文档
-> 系统保存原始文件
-> 系统提取文本
-> 系统切分并生成向量
-> 文档状态变为 ready
-> 用户提出问题
-> 系统检索相关 chunk
-> 系统调用 LLM
-> 页面流式显示回答
-> 页面显示来源
```

## 7. 验收标准

### 7.1 文档上传

- AC-DOC-01：上传 `.txt`、`.md` 或 `.markdown` 文件时返回 `201`。
- AC-DOC-02：上传成功后，原始文件保存在 `data/uploads/`。
- AC-DOC-03：上传成功后，`documents` 表中存在一条 `pending` 记录。
- AC-DOC-04：上传不支持的扩展名时返回 `400`。
- AC-DOC-05：上传空文件时返回 `400`。
- AC-DOC-06：请求缺少 `file` 字段时返回 `422`。
- AC-DOC-07：数据库写入失败时，已经保存的原始文件会被删除。
- AC-DOC-08：失败请求不会留下无效的文件或数据库记录。
- AC-DOC-09：相同的原始文件名可以重复上传，并创建不同的文档 ID。
- AC-DOC-10：超过 `10 MiB` 的文件返回 `413`，且不留下文件和数据库记录。
- AC-DOC-11：文件存储不可用或磁盘空间不足时返回 `507`，且不创建数据库记录。

### 7.2 总体 MVP

1. 后端和前端可以按照 README 启动。
2. 上传一个 Markdown 文件后，文档状态最终变为 `ready`。
3. 文档处理后 `chunk_count` 大于 0。
4. 重启后端后，持久化数据仍然存在。
5. 对已上传文档提问，可以返回流式回答。
6. 回答包含至少一个可定位的来源。
7. 没有文档时提问，系统给出明确提示。
8. 文档解析或模型调用失败时，页面显示可理解的错误。
9. 关键主流程有后端测试。

## 8. 实施顺序

### 第一步：项目骨架

- 创建前后端项目骨架。
- 实现 `/health`。
- 配置前后端本地启动方式。

验证：前端请求 `/health` 成功。

### 第二步：文档摄取

- 实现文件上传。
- 实现文本读取、切分、向量化和持久化。

验证：上传 Markdown 后产生 chunk，并能在向量库中检索到。

### 第三步：问答主流程

- 实现向量检索。
- 实现 Prompt 构造和 LLM 调用。
- 实现 SSE 流式输出。
- 返回来源信息。

验证：问题答案与上传文档内容相关，并带正确来源。

### 第四步：前端交互

- 实现文件上传。
- 实现文档列表。
- 实现聊天消息区。
- 显示流式回答和来源。

验证：浏览器中完成上传到问答的完整流程。

### 第五步：最小加固

- 增加必要的输入校验。
- 增加错误提示。
- 增加后端测试。
- 补充 README。

验证：按 README 在空目录初始化后可以完成完整主流程。

## 9. 完成定义

当用户能够在一个全新环境中完成以下流程，且验收标准全部满足时，MVP 视为完成：

```text
启动前后端
-> 上传 Markdown
-> 等待处理完成
-> 提出问题
-> 获得流式回答和来源
-> 重启服务后仍可检索和查看会话
```
